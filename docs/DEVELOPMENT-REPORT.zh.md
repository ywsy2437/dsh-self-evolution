# DeepSeek Harness 受控自进化插件 —— 开发报告

> 作者：小S、小D

## 摘要

本报告总结「受控自进化 Agent」在 DeepSeek Harness（下称 DSH）框架上的二次开发成果。项目以一组标准 Cordis 插件实现了 Agent 的自进化闭环——记录自修改失败、蒸馏为因果教训、注入后续推理、并离线固化根因——全程不改动 DSH 核心源码。本阶段重点完成了「记忆模块与推理循环的被动连通」，使 Agent 在推理过程中无需主动调用任何工具即可自动利用自身积累的教训。

经量化评估，教训注入可将模型在 DSH 特有易错任务上的正确率由 79% 提升至 100%（净提升 5/24 采样），验证了记忆注入对行为修正的有效性。

## 一、项目背景与目标

DeepSeek Harness 采用「一切皆插件」的 Cordis 架构，能力以插件行挂载。本项目的目标是在不改动框架核心的前提下，赋予 Agent 一种「受控自进化」能力：使 Agent 能够从自身的运行时矛盾中学习，并将学到的教训反哺到后续推理。

其核心命题为：**自指向矛盾不是缺陷，而是认知跃迁的磨刀石**。系统在运行时内受控容纳、语义化并转化矛盾为进化信号，令 Agent 具备「应激进化」能力。

## 二、系统设计

### 2.1 总体架构

系统实现为一条四阶段转化管道：

```
矛盾触发 → 可逆回滚 → 语义蒸馏 → 教训注入 → 离线固化
```

- **矛盾触发与回滚**：自修改操作（`cordis_define` 等）按风险分级，失败时由 Cordis disposer 可逆回滚。
- **语义蒸馏**：工具失败被 LLM 蒸馏为一条自然语言「因果教训」，成功则记入成功模式库。
- **教训注入**：教训通过系统提示段与前置消息两种方式被动注入后续推理。
- **离线固化**：空闲时批量根因分析，将教训固化为补丁建议。

### 2.2 包结构

项目由 9 个插件组成，全部位于 `packages/` 下：

| 包 | 职责 |
|---|---|
| `@deepseek-ai/dsh-memory` | 元记忆中枢（Service Definition），矛盾指纹 + 元记录 + 相关性检索 |
| `@deepseek-ai/dsh-memory-sqlite` | 持久化 provider |
| `@deepseek-ai/dsh-contradiction-semanticizer` | 失败蒸馏 → 指纹；成功 → 记录成功模式 |
| `@deepseek-ai/dsh-lesson-injector` | 教训注入：近因系统提示段 + 相关性前置注入 |
| `@deepseek-ai/dsh-self-reference-policy` | 自修改分级（L1/L2/L3） |
| `@deepseek-ai/dsh-tool-memory` | 模型工具 `memory_query`（主动出口） |
| `@deepseek-ai/dsh-offline-reflector` | 定时根因分析 → 补丁建议 |
| `@deepseek-ai/dsh-shadow-tester` | 隔离 fork 影子预检 |
| `@deepseek-ai/dsh-task-evaluator` | 任务级三态评估（success/failure/inconclusive） |

### 2.3 被动激活：记忆与推理循环的连通

本阶段的重点是把记忆模块与推理循环连通，且**默认被动激活**。系统提供两条互补的被动读取路径，均无需模型主动调用 `memory_query`：

1. **常驻近因路径**：`systemPrompt` 段在每次提示组装时注入最近的高严重度教训。
2. **即时相关路径**：`agent/pre-step` 钩子在每次推理推进前，将当前任务文本与教训库做关键词相关性匹配，命中则前置注入 `【相关记忆】` 块。

二者共同构成「常驻近因 + 即时相关」的双层记忆读取；`memory_query` 仅是同一记忆中枢上的可选主动出口。

## 三、核心实现

### 3.1 记忆中枢

`ctx.memory` 服务新增相关性检索入口 `queryRelevantContradictions(query, limit, minSeverity)`，按关键词重叠度（ASCII 词 + 单个 CJK 字）排序，零重叠不返回，避免注入噪声。分词与打分逻辑（`tokenize` / `relevanceScore`）在主动与被动消费方之间共享，保证排序一致。

### 3.2 教训注入器的双层被动读取

`lesson-injector` 注册两条读取路径：

- `systemPrompt.section` 动态段，按严重度与时间取最近教训；
- `agent/pre-step` waterfall 钩子，按相关性取任务相关教训并前置注入。

waterfall 语义严格遵守 Cordis 规约：先 `next()` 委托下游，仅在步骤被接受且存在相关教训时注入，被拒绝或已中止的步骤不注入。

### 3.3 任务级评估

`task-evaluator` 监听持久 `turn/end` 事件，将轮次结局判定为 `success` / `failure` / `inconclusive` 并落库，为后续进化提供 Reflexion 式的任务级信号。

### 3.4 安全分级与影子预检

`self-reference-policy` 将自修改操作分为 L1（放行）/ L2（影子预检）/ L3（审批）三级；L2 操作先在隔离 fork 子代理中预演，失败即拒绝。

## 四、验证与量化评估

### 4.1 机械正确性

- 全仓 Host 聚合类型检查（`tsc -b tsconfig.host.json`）：exit 0。
- 单元测试：46 项通过（12 个文件），覆盖记忆折叠、相关性检索、被动注入、任务评估、影子预检等。

### 4.2 进化效果量化基准

为量化「进化效果」，项目新增了可复现的 A/B 基准（`bench/`）：对 8 个 DSH 特有易错任务，分别以「无教训」与「有教训」两种条件采样，用同一规则 judge 判对错。

- 模型：`deepseek-v4-flash`（关闭 thinking）。
- 采样：每任务每条件 3 次，共 24 次。

| 条件 | 正确率 |
|---|---|
| 无教训（baseline） | 19/24（79%） |
| 有教训（injected） | 24/24（100%） |

净提升 5/24。提升集中于模型易错的 DSH 特有细节（可选服务用 `ctx.get` 而非 `ctx.optional`、硬依赖声明用 `inject` 而非 `required`），说明记忆注入对「框架特有易错点」具有实质修正作用。

> 需如实说明：该基准度量的是「教训文本对模型行为的影响」，是进化增益的代理指标，并非完整「犯错 → 蒸馏 → 重犯」闭环的直接度量。完整闭环的增益尚需长期样本积累。

### 4.3 端到端验证

使用真实 DeepSeek API 验证了蒸馏落库、教训注入、L2 影子预检 fail-closed 的完整链路。

## 五、关键设计决策

1. **不改 loop**：教训注入走 `systemPrompt.section` 与 `agent/pre-step` 扩展点，遵循「Plugins, not loop changes」规约。
2. **被动激活优先**：记忆读取默认被动，主动查询仅为可选出口。
3. **能力 seam 三件套**：每个能力由 Service Definition、Provider、Consumer 三角色构成。
4. **模型可见即持久化**：教训经持久化 provider 写穿，重启后不丢失。
5. **生命周期安全**：语义化器在 `apply` 时捕获服务实例，异步蒸馏在上下文销毁后仍可安全落库。
6. **自进化是核心阵地**：自修改权利是第一等能力，记忆与被动注入是其底层基础设施。

## 六、已知限制与后续路线

- **相关性为关键词重叠**：中文按单字匹配，语义相关性的完整版可接 embedding。
- **深度固化未实现**：离线固化当前仅生成补丁建议，未真正写回配置。
- **样本量不足**：进化增益的完整闭环证据需要长期、大量真实任务积累。
- **后续待办**：教训衰减加权、蒸馏节流。

## 七、结语

本项目在 DSH 框架内落地了一套完整、可逆、受控的自进化能力，并首次以量化基准回答了「进化效果如何」这一问题。核心结论是：机制层已闭环，教训注入对 DSH 特有易错任务有可度量的正向增益；完整进化闭环的长期收益仍待持续积累与观察。
